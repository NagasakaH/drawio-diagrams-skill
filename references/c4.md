> 実行はすべて `node scripts/drawio-cli.mjs c4 ...` 経由。

# C4 Container 図生成スキル (`drawio-c4`)

JSON spec を描画して `.drawio` XML および `.drawio.png`（元XML埋め込み済み・draw.io再編集可能）を
生成する。Pure Node.js (.mjs) のみで動作し、外部 npm 依存はゼロ。
C4 model の **Container 段**（Person → Software System の境界 → Container / Database / Queue →
外部システム）を、公式 C4 に近い配色とプロトコルラベル付き矢印で描く。

---

## デフォルトの描画方針

- **レイアウト**: spec の `row` / `col` を優先（0 始まり整数）。左右は人 → 自社 → 外部、
  上下は同期フロー → 非同期フローの順に置くと読みやすい。水平間隔 150px・垂直間隔 116px 基準。
- **要素カード**: `名前`（13px 太字白）+ `[Badge]  tech`（10px）+ `description`（10px）。
  種別で形状と色が決まる（下表）。データストアは `shape=cylinder3;` の円柱で描く。
- **Person**: 濃紺 (`#08427B`) の角丸カード。境界の外に置く。
- **境界 (System Boundary)**: 破線フレーム + 左下に `[Software System] 名前`。
  メンバー要素の外接矩形から自動で枠を広げる（左右 34px・上 30px・下 52px の余白）。
- **関係線**: `sync` は青実線 + 塗り三角、`async` は水色破線 + open arrow、
  `external` はグレー。ラベルは `HTTPS / JSON`・`SQL / TLS`・`Async Event: order.placed` のように
  プロトコルやイベント名を書き、`labelBackgroundColor=#FFFFFF` を付ける。
- **配線**: orthogonal。同一辺に複数本寄る場合はポートを 0.28〜0.72 へ分散し、
  他要素を貫く直線は空白帯へ回避ウェイポイントを投入する。
- **ヘッダー**: 左端アクセントバー (#1D4ED8) + 左寄せタイトル / サブタイトル + 細区切り線、
  右上に凡例（Person / Container / Database / Queue / External / 同期 / 非同期 / 境界枠）。

---

## 実行手順

### 1. JSON spec から直接描画（最短1コマンド）

```bash
node scripts/drawio-cli.mjs c4 \
  --spec /path/to/c4-spec.json \
  --output /path/to/c4-container.drawio.png
```

`--output` から `.drawio` XML のパスを自動決定する（`xxx.drawio.png` → `xxx.drawio`）。
明示指定は `--xml-out`、タイトル上書きは `--title` / `--subtitle`、PNG解像度は `--scale`（既定 2）。
`--no-png` で XML のみ生成も可。`.svg` 出力は出力拡張子で自動判定。

### 2. 実在プロジェクトから起こす手順

1. リポジトリの README / マニフェストから「実行単位」を列挙する（Web / App / API / Worker / DB / Queue）。
2. 人が使う角色（Customer / Admin / Operator）を `kind: "person"` で起こす。
3. 第三者 SaaS（決済・メール・認証）は `kind: "external"` にして境界の外へ置く。
4. 各関係にプロトコルを書き込む（`HTTPS / JSON`、`gRPC / protobuf`、`SQL / TLS`、`RESP`、`Async Event`）。
   ここが C4 の要点なので空欄にしない。
5. 境界をまたぐ線を減らすよう `row` / `col` を整える。

### 3. 目視検証（必須）

生成された `.drawio.png` を画像読み込みで確認し、カード内のテキスト切れ・境界枠と線の衝突・
ラベルの重なりをチェックしてからユーザーへ報告する。
`node scripts/check-layout.mjs <生成 .drawio>` で機械検査もできる。

# JSON spec リファレンス (`drawio-c4`)

`build-c4.mjs --spec` に渡す JSON の形式。最上位キーは `title` / `subtitle` / `boundaries` /
`elements` / `relationships`。必須は `elements` のみ（空配列はエラー）。

```json
{
  "title": "E コマースプラットフォーム（C4 Container レベル）",
  "subtitle": "1行の補足説明（任意）",
  "boundaries": [
    { "id": "shop", "label": "E-commerce Platform", "kind": "Software System" }
  ],
  "elements": [ ... ],
  "relationships": [ ... ]
}
```

## `elements[]` — C4 要素

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `id` | ○* | 図内一意の参照キー（`relationships` から参照）。*`name` だけで書くことも可 |
| `name` | ○ | 要素名（`Order Service` など） |
| `kind` | | `container`（既定）/ `person` / `database` / `queue` / `external` |
| `tech` | | 技術名（`Go 1.23 / gRPC`）。省略見出しは `[Badge]` のみ |
| `techLabel` | | 見出し行を完全に上書きしたいときだけ使う（通常は `tech` で十分） |
| `description` | | 役割の一言（カード下段、折り返し可） |
| `boundary` | | 所属境界の `id`。`boundaries[]` に無い id なら暗黙に枠を追加 |
| `row` / `col` | | グリッド配置（0 始まりの整数）。未指定は自動 |

### kind と描画

| `kind` | バッジ | 形状 / 配色 |
| --- | --- | --- |
| `person` | `[Person]` | 角丸 176×92、濃紺 `#08427B` / `#06315C`、白文字 |
| `container` | `[Container]` | 角丸 232×104、青 `#1168BD` / `#0B4E93`、白文字 |
| `database` | `[Database]` | 円柱 (`shape=cylinder3`) 208×116、`#0E4C8A` / `#093A6B` |
| `queue` | `[Queue / Stream]` | 角丸 228×104、青緑 `#0E7490` / `#155E75` |
| `external` | `[External System]` | 角丸 212×96、グレー `#F1F5F9` / `#64748B`、濃色文字 |

- `tech` を長く書くとカードは自動で縦に伸びる（折り返しは renderer の文字幅推定で計算）。
- Redis などキャッシュは `database` のまま `tech` に `Redis 7` と書くのが C4 流儀。

## `relationships[]` — 依存・呼び出し

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `from` | ○ | 呼び出し側（矢印が出る側）の要素 `id` |
| `to` | ○ | 呼び出される側の要素 `id` |
| `label` | | プロトコル + 用途（`HTTPS / JSON`、`SQL / TLS`、`Async Event: order.placed`） |
| `kind` | | `sync`（既定）/ `async` / `external` |

| `kind` | 描画 |
| --- | --- |
| `sync` | 青実線 (`#1D4ED8`) + 塗り三角 |
| `async` | 水色破線 (`#0E7490`) + open arrow |
| `external` | グレー実線 (`#64748B`) + 塗り三角 |

- 同じ要素ペアの往復は自動的にラベルを上下（左右）へ分ける。
- 複数本が同じ辺から出るときは出口ポートを等間隔に分散する。

## `boundaries[]` — システム境界の破線枠（任意）

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `id` | ○ | `elements[].boundary` から参照される id |
| `label` | | 枠左下に表示する名前（既定は `id`） |
| `kind` | | 前置ラベル。`Software System` を常用 → `[Software System] 名前` |

`boundaries[]` を書かなくても `elements[].boundary` だけで暗黙に枠が生成される。
Person と外部システムは `boundary` を付けない（境界の外に出る）。
